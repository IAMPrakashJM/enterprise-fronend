A development delivery is not automatically a tagged, published or deployed release. Use `unreleased/` until an actual release/candidate identity is established. Create a versioned release directory only for an agreed real version, and keep the corresponding source/tag/artifact evidence.

Every record needs scope, user impact, integration/defaults, compatibility/data changes, policy/security impact, errors/recovery, test scope, source identity, remaining work, rollback and publication status. Record backend migrations and native/browser compatibility when applicable. Use “not applicable” with a reason instead of omitting the topic.

Older frontend feature notes may describe earlier successful deployments. Those statements do not apply automatically to the current uncommitted Library corrections. Read the exact change's delivery record.
